# Hardware verification needed before flashing

To be collected from the real device:

1. The full SKU and a photo of the label: `K151` or `K151-R`.
2. The firmware version shown by the device or by M5Burner.
3. The board/target detected over USB and the update mode available.
4. The presence and version of microphone, speaker, camera and servo motors.
5. The link to the product page or to the bill of materials bought.

Until these data are available, the repository holds only a stub and no flashing procedure.

## Flash carried out (9 November 2026, with the user's "yes")

Port: `/dev/cu.usbmodem2101`. Tool: `esptool` 5.6.0.

1. Erase the whole memory (the old `otadata` would fall inside the new nvs area): `esptool -p PORT erase-flash`.
2. Write the host: `esptool --chip esp32s3 -p PORT -b 460800 write-flash --flash-mode dio --flash-size 16MB --flash-freq 80m 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 xs_esp32.bin` (files in `firmware/artifacts/host/`, check the SHA-256 values in `build-info.json` first).
3. Write the MOD into the `xs` partition: `esptool -p PORT write-flash 0x910000 firmware/artifacts/robottino-portrait.xsa`.
4. Restart, watch the serial logs, then calibration and the `verified` / `calibrated` switches.

With voice in the queue this happens at every turn: while Robottino talks, the program stays still almost all the time, the network is read in bursts and the speaker runs dry (choppiness). Moddable's `ChatAudioIO` does not suffer from it because it reads the network in a separate thread;
